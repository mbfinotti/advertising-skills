# Brightfin — Format Decision & Deliverables

_(Pre-brief decisions, resolved per `ad-creative-brief` skill. Definitions used below: **Concept** = one brief, one idea. **Format** = execution container. **Iteration** = a variant changing one element of an existing concept, not a new concept.)_

---

## Decision 1: Format for the launch brief

**Recommendation: Static. Video/UGC is deferred to next sprint — not deleted.**

The skill's efficiency ranking is fixed: **static > search > video/UGC**. Video/UGC sits at the top of the _value_ axis (strongest learning, isolates all three hook layers) but dead last on _efficiency_ — creator sourcing, shoot, rights and revision rounds run "a week of coordination, not hours."

Your situation matches the rule for overriding value with efficiency exactly:

| Constraint                                                | Effect                                                                                                                            |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 6 business days, hard date (App Store feature)            | No slack for creator sourcing → shoot → revisions → rights sign-off. A UGC program from zero creators does not clear this window. |
| No creators lined up                                      | The most time-consuming step (sourcing, vetting, casting) hasn't started.                                                         |
| One in-house designer, no video editor/UGC producer named | Capacity matches static production, not a shoot.                                                                                  |

A hard deadline is explicitly the one condition the skill calls out for pinning to static **without removing video/UGC from the menu**. The correct label is **"deferred to the next sprint,"** never "deleted" — deletion is reserved for cases where creator rights or claim approval are categorically unavailable, which isn't the case here; you just don't have time _for this launch date_.

**What to do in parallel, this sprint, at near-zero cost to the static work:** start creator sourcing and rights conversations now. That's the expensive part of video/UGC — running it in the background means the _next_ brief starts as an editing/scripting job instead of from zero, which is the actual condition that would justify promoting UGC over the ratio later.

## Decision 2: Do not drop static permanently

**Recommendation: Keep static as a permanent, standing format. Reject "statics are dead."**

Two things in the skill directly contradict that framing:

1. **Static is the default first concept**, described as "the cheapest honest at-bat" — not a fallback format, a standing one. There is no criterion in the skill for deleting static permanently; the only permanent-deletion triggers named are (a) UGC when creator rights/approval are categorically unavailable, and (b) search when no keyword demand exists. "Statics underperform" isn't one of them, and even underperformance is a _demote_, never a _delete_ — deleting a live rung just means the next sprint re-briefs it anyway without anyone noticing it was supposed to be gone.
2. **"Statics are dead" is exactly the shape of claim the skill warns against treating as fact.** It's the same pattern as the retired "20% text rule" folklore: an unverified, vendor-post-style claim circulating without a citation. The skill's rule is "say so rather than encoding folklore as a rule" — apply that here too. If you have account-specific data showing static underperforming _for Brightfin_, that's a real, re-rankable signal; a general industry rumor is not.

Format choice is also not binary. Static and video/UGC sit on different points of the same efficiency/value tradeoff and are meant to coexist in rotation — video/UGC for compounding learning and the strongest hook-layer isolation once you have a creator roster and footage library, static for fast, cheap at-bats and message validation in between. Permanently removing static removes your only fast rung and makes every future test dependent on creator availability and shoot scheduling.

## Deliverables (Brief field 7 — for the launch concept, format: Static)

Given one designer and a 6-business-day hard deadline, sized to what one person can actually produce at production quality with one consolidated revision round:

| Field                    | Value                                                                                                                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Arithmetic**           | 2 concepts (NEW, angle-diverse — not two versions of one idea) × 2 offer-framing variants each (IT — default first static test variable per the skill) × 2 ratios (1:1 feed, 9:16 story/reel) = **8 exports** |
| **Iteration vs net-new** | 2 files `NEW` (the two base layouts) · 6 files `IT` (offer-copy swaps + ratio resizes of those two layouts)                                                                                                   |
| **Naming convention**    | `<Concept>_V<n>_<Ratio>_<TestVariable>` — e.g. `PainFirst_V1_1x1_OfferFraming`, `PainFirst_V1_9x16_OfferFraming`, `TimeSaved_V1_1x1_OfferFraming`                                                             |
| **Revision cap**         | 1 consolidated round, agreed now — the deadline doesn't survive a second round; one named approver only                                                                                                       |

**Assumption flagged:** ratios above (1:1, 9:16) assume Meta-style feed + Reels/Stories placement, since platform wasn't confirmed. Pull the platform's currently published safe zones before export in either case — don't hardcode pixel numbers, preview in-placement.

**Note carried into the next brief:** log this deferral in the angle bank now — "Video/UGC deferred to next sprint, not deleted; reason: 6-day hard deadline, zero creators sourced at brief time." That's what keeps it from silently falling off the menu.
